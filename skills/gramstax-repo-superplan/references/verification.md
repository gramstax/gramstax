# Verification

A plan is only as good as the evidence that closes its phases. This reference maps change types to the smallest credible gate, then to the full gate.

## Fresh-Evidence Rule

Every claim in a plan or execution report must be backed by a command run in the current workspace state. Prior output, a subagent summary, or "the code looks right" is not evidence.

Record:

```markdown
| Claim | Command | Exit | Evidence |
| --- | --- | --- | --- |
| CLI still boots | `bun run --cwd example/1-complex start --help` | 0 | Usage printed; no config import error |
| Core tests pass | `bun test packages/gramstax/test` | 0 | 1909 pass, 0 fail |
```

## Change-Type Gates

| Change type | Minimum gate | Add when |
| --- | --- | --- |
| Skill/docs only | `git diff --check`; scanner tests | `bun run build:docs` if TSDoc/API docs changed |
| Core library | `bun test packages/gramstax/test`; `bun run ci:check` | `bun run build` if exports/dist change |
| CLI / config / boot | Core gate + `bun run --cwd example/1-complex start --help` | Built/packed binary smoke; `bun run build` |
| Scaffolder / templates | `bun test packages/create-gramstax/test`; `bun run ci:check` | Generate a throwaway project and run its tests |
| LMDB | `bun test packages/lmdb/test`; `bun run ci:check` | `bun run build:packages` if exports change |
| Worker thread | `bun test packages/worker-thread/test`; `bun run ci:check` | `bun run build:packages` if exports change |
| Examples / e2e | `bun run test:example` | `bun run build` when examples load built packages |
| Authored docs / README | Scanner tests; link review | `bun run build:docs` when docs are generated from TSDoc |
| Cross-package / release | `bun run ci:test`; `bun run build`; `git diff --check` | Packed-install smoke; release dry run |

## Exact Commands

### Typecheck and lint

```bash
bun run ci:check
bun run ci:check:packages
bun run lint
bun run lint:packages
```

`ci:check` runs `tsc --noEmit` for the root plus `gramstax`, `create-gramstax`, `lmdb`, and `worker-thread`, then `biome lint`. There is no separate format check script; `biome lint` is the style gate.

### Tests

```bash
bun test packages/gramstax/test
bun test packages/create-gramstax/test
bun test packages/lmdb/test
bun test packages/worker-thread/test
bun run test:example
bun run test:packages
bun run ci:test
```

Use a single file when iterating:

```bash
bun test packages/gramstax/test/cli.env.test.ts
bun test --filter "TemplateEngine"
```

### Build and docs

```bash
bun run build
bun run build:packages
bun run build:docs
```

`build:docs` regenerates `docs-site/reference/**` and the package docs. Run it only when source TSDoc/API docs changed, and never hand-edit its output.

### CLI smoke

```bash
bun run --cwd example/1-complex start --help
```

Use a generated or packed project when the change affects the published binary, `Bun.serve`, `--bundle`, or serverless target emission.

### Workspace hygiene

```bash
git diff --check
git status --short
```

`git diff --check` catches trailing whitespace and conflict markers. `git status --short` catches generated files, untracked plans, and accidental edits.

## Generated Docs

- `docs-site/reference/**` is generated by CI and `bun run build:docs`.
- `packages/*/docs/{markdown,yaml}` is staged generated output.
- Authored docs live under `docs-site/guides/**`, `docs/**`, and READMEs.
- A docs-only change to generated reference output is a defect: change the TSDoc/source instead.

## Release Gates

Only when the user asks for a release:

```bash
bun run ci:test
bun run build
bun run dry-run
```

Do not run `version`, `release`, `publish`, tag, or push without an explicit request. A plan may propose a conventional commit message, but git operations remain separate.

## What Does Not Count

- A subagent saying "tests pass".
- A previous run before the latest edit.
- `bun run lint` output from a different branch.
- A build that only reuses cache without confirming the changed package emitted.
- A manual smoke that was not written down with its command.
- A plan checkbox marked complete without evidence.
- A green test that asserts the old behavior because the test was weakened.

## Failure Protocol

1. Capture the exact failing command and output.
2. Identify whether the failure is in the task, its test, or a prior assumption.
3. Fix the smallest cause; do not weaken the gate.
4. Re-run RED/GREEN if the test changed.
5. If the failure changes scope or architecture, stop and switch to REFINE/RECONCILE.
6. Record the failure and resolution in the execution report.

## Final Gate Template

```markdown
## Final Gate

| Check | Command | Result |
| --- | --- | --- |
| Typecheck | `bun run ci:check` | ✅ exit 0 |
| Tests | `bun test packages/gramstax/test` | ✅ 1909 pass, 0 fail |
| Examples | `bun run test:example` | ✅ 154 pass, 0 fail |
| Build | `bun run build` | ✅ exit 0 |
| Whitespace | `git diff --check` | ✅ no output |

**Evidence captured:** YYYY-MM-DD HH:MM
**Workspace:** <branch / commit / dirty files>
```
