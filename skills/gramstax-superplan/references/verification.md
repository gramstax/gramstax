# Verification For Gramstax Apps

A plan is only as good as the evidence that closes its phases. This reference maps app change types to the smallest credible gate, then to the full app gate.

## Fresh-Evidence Rule

Every claim in a plan or execution report must be backed by a command run in the current app workspace state. Prior output, a subagent summary, or “the code looks right” is not evidence.

Record:

```markdown
| Claim | Command | Exit | Evidence |
| --- | --- | --- | --- |
| Page flow still works | `bun run test:e2e` | 0 | 24 pass, 0 fail |
| App still boots | `bun run start -- --help` | 0 | Usage printed; no config import error |
```

## Read package.json First

The app owns its command names. Read `package.json` before naming any gate. Do not import monorepo scripts such as `bun run ci:check` into an app plan. A greenfield plan has no `package.json` until the scaffold phase; use the generated project's scripts once it exists.

Typical generated project:

| Script | Command |
| --- | --- |
| `dev` | `bun run dev` |
| `start` | `bun run start` |
| `build:gramstax` | `bun run build:gramstax` |
| `typecheck` | `bun run typecheck` |
| `lint` | `bun run lint` |
| `test` | `bun run test` |
| `test:e2e` | `bun run test:e2e` |
| `test:all` | `bun run test:all` |

A standalone app may name the build script `build`, use `biome check`, or pin older scripts. Use the actual names.

## Change-Type Gates

| Change type | Minimum gate | Add when |
| --- | --- | --- |
| Pure helper / unit logic | `bun run test` | Typecheck |
| Page / callback / session | `bun run test` + `bun run test:e2e` | Manual Telegram flow |
| Template / keyboard | Relevant e2e suite | Visual/manual message check |
| Config / env / deploy | `bun run typecheck` + `bun run start -- --help` | `bun run build:gramstax`; webhook/serverless smoke |
| LMDB schema / repository | DB unit tests | Restart/migration check |
| Worker / job | Worker tests | Startup failure and shutdown check |
| Dependency upgrade | `bun run test:all` | Build, start smoke, and manual journey |
| Docs only | `git diff --check` | Link/review check |
| Release candidate | `bun run test:all` + `bun run typecheck` + `bun run lint` + build | Manual end-to-end journey |

## Exact Commands

### Typecheck and lint

```bash
bun run typecheck
bun run lint
```

If the scripts are missing:

```bash
bunx tsc --noEmit
bunx biome lint .
```

### Tests

```bash
bun run test
bun run test:e2e
bun run test:all
```

If the scripts are missing:

```bash
bun test test/
bun test e2e/
```

Use a single file when iterating:

```bash
bun test test/checkout.test.ts
bun test e2e/checkout.test.ts
```

### Build

```bash
bun run build:gramstax   # generated project
bun run build            # standalone app may use this
```

`gramstax build` writes `.gramstax/**`. Never hand-edit that tree; change the page/config source and rebuild.

### Start / boot smoke

```bash
bun run start -- --help
# or, when the CLI is available directly:
bunx gramstax start --help
```

A boot smoke proves config import and CLI startup. It does not replace an e2e journey.

### Manual Telegram check

```bash
bun run dev
```

Then exercise the real bot flow. Record the exact steps and expected messages/keyboards. Do not claim a manual check you did not perform.

### Workspace hygiene

```bash
git diff --check
git status --short
```

`git diff --check` catches trailing whitespace and conflict markers. `git status --short` catches generated files, secrets, and accidental edits.

## Generated and Runtime Files

- `.gramstax/**` is generated by `gramstax build`; do not hand-edit.
- `data/**`, `backups/**`, and `logs/**` are runtime state; do not include them in a code change.
- `.env` is local secret state; document safe variable names in the README, or update `.env.example` if the app keeps one.
- `node_modules/**` is installed dependency state; never edit it.

## Framework Upgrade Gate

When the plan changes `gramstax`, `@gramstax/lmdb`, or `@gramstax/worker-thread`:

1. Record old and new versions from `package.json`.
2. Read the migration/README for those versions.
3. Run `bun run test:all`.
4. Run the build and start smoke.
5. Exercise the highest-risk page or worker journey manually.
6. Note any data migration or rollback step.

Do not plan a framework upgrade using only the current `main` docs if the app is moving from an older major.

## What Does Not Count

- A subagent saying “tests pass”.
- A previous run before the latest edit.
- A lint output from a different branch.
- A build that only reuses cache without confirming the app emitted.
- A manual smoke that was not written down with its command.
- A plan checkbox marked complete without evidence.
- A green test that asserts the old behavior because the test was weakened.

## Failure Protocol

1. Capture the exact failing command and output.
2. Identify whether the failure is in the task, its test, or a prior assumption.
3. Fix the smallest cause; do not weaken the gate.
4. Re-run RED/GREEN if the test changed.
5. If the failure changes scope or architecture, stop and switch to REFINE/RECONCILE.
6. Record the failure and resolution in the execution report.

## Final Gate Template

```markdown
## Final Gate

| Check | Command | Result |
| --- | --- | --- |
| Typecheck | `bun run typecheck` | ✅ exit 0 |
| Lint | `bun run lint` | ✅ exit 0 |
| Unit tests | `bun run test` | ✅ 0 fail |
| E2E tests | `bun run test:e2e` | ✅ 0 fail |
| Build | `bun run build:gramstax` | ✅ exit 0 |
| Boot smoke | `bun run start -- --help` | ✅ usage printed |
| Whitespace | `git diff --check` | ✅ no output |

**Evidence captured:** YYYY-MM-DD HH:MM
**Workspace:** <branch / commit / dirty files>
**Framework version:** `gramstax <version>`
```
