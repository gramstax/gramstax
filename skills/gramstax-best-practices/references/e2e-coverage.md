# e2e-coverage

**Verdict:** a suite is complete only when every page, handler entry point, render route, interactive state, session transition, guard direction, locale, and fallback has a test that fails when that behavior is deleted. A mirrored file proves a page is *registered*; it proves nothing about behavior.

## Why

File mirroring answers one question: "does `src/pages/foo/bar.ts` have `e2e/foo/bar.test.ts`?" It cannot see that `handleArgsCallbackQueryData`, two `g*` process branches, the denial path, and the Indonesian variant are untested. Suites generated by agents drift to one happy-path assertion per file because nothing forces the inventory to be enumerated. This file makes that inventory mechanical and its coverage auditable.

"100% e2e" here means **every observable behavior has a test**, not every source line. Test through updates and captured API calls; never reach into page internals.

## How to use these files

1. `e2e-setup.md` — once per project: build the harness, fixtures, isolation, mirror.
2. `e2e-coverage.md` (this file) — per page: derive the inventory, fill the ledger, cover all seven layers.
3. `e2e-validation.md` — per assertion: choose the method/payload checks that prove the behavior.
4. `e2e-flows.md` — per flow: drive the sequence a user takes, including invalid, denied, and cross-user paths.

A change is not complete until the mirrored test, the ledger row, and the assertion all exist. Reviewers check the ledger, not the test count.

## Execution protocol for an AI agent

Follow this order; do not start writing assertions before the inventory exists.

1. Read `src/pages`, `src/base`, `src/guards`, `src/core/bot.ts`, and `e2e/setup.ts`.
2. Run the inventory scans in Rule 0 and list every handler, state, render call, gate, locale, and fallback.
3. Create or refresh `e2e/COVERAGE.md` with one row per handler/state/hook, a real trigger, a test file, and the concrete assertion.
4. Write the mirrored test for each row. Add the invalid, cancel, deny, locale, and fallback cases that the page declares.
5. Assert the Bot API method and the template-derived payload; never stop at `length > 0`.
6. Run `bun run test:e2e:check`. Fix every missing row, missing test file, and orphan test.
7. Run `bun run test:e2e`. Fix the assertion or the page, not the ledger, when behavior is wrong.
8. Re-read the ledger against the source and delete stale rows. Stop only when the definition of done is met.

## The seven coverage layers

| # | Layer | Question it answers | Minimum proof |
| --- | --- | --- | --- |
| 1 | Mirror | Does every page have a test file at the mirrored path? | `check-e2e-mirror` exits 0 |
| 2 | Entry points | Is every `handle*` the page defines reachable in a test? | One test per handler row in the ledger |
| 3 | Render routes | Does every `render*` call produce the intended Bot API method? | Method + payload assertion |
| 4 | States | Is every `show`/`process` branch, including invalid input, exercised? | One test per interactive state |
| 5 | Guards | Do allow **and** deny both behave as designed? | Two users, two assertions |
| 6 | Locales | Does every declared `lang` variant render? | `gmsg`/`gkb`/`gmedia` with that lang |
| 7 | Fallbacks | Do unknown/unsupported updates land somewhere safe? | Fallback page or free handler assertion |

Layers 2–6 are per page. Layers 1 and 7 are project-wide.

## Rule 0 — derive the inventory from source, never from memory

Run these from the project root before writing tests. The output is the coverage ledger's input.

```bash
# every handler the page tree can dispatch (includes inherited base-class handlers when
# you also scan src/base and src/core)
rg -n --no-heading "^\s+(async\s+)?handle[A-Za-z0-9_]*\s*\(" src/pages src/base src/core

# every declared intent and arg builder
rg -n --no-heading "static\s+data\s*=|buildData\(|intentCallbackQueryData|intentText|intentCommandText" src/pages

# every render call, broadcast, and stream
rg -n --no-heading "render[A-Z][A-Za-z]*\(|replyWith[A-Z][A-Za-z]*\(|broadcast\s*:" src/pages

# every gate and hook
rg -n --no-heading "hookBeforeRoute|hookAfterRoute|hookErrorPage|hookNotFoundPage|GuardBase" src

# every template state and locale
rg -n --no-heading "<g-base|<g-message|<g-keyboard|<g-media|<g-ifelse|<g-switch|lang=" src/pages
```

Write the result into `e2e/COVERAGE.md` as a ledger (template below). A handler with no ledger row is untested, even if the file mirror passes.

## Rule 1 — every handler entry point gets a test

### Dispatch matrix

Trigger each handler with the update shape its name implies. `intent` is `Page.data.intentCallbackQueryData` (default: the page name, e.g. `start/random`).

| Handler | Trigger | Notes |
| --- | --- | --- |
| `handleCallbackQueryData` | `e2e.sendCallbackQuery(intent, user)` | Exact intent only. Auto-edit is expected on callbacks. |
| `handleArgsCallbackQueryData` | ``e2e.sendCallbackQuery(`${intent}:${a1}:${a2}`, user)`` or `Page.data.callbackQueryData(a1, a2).result` | Requires `static data = this.buildData((a1, a2) => [a1, a2])`. Args are colon-separated. |
| `handleText` | `e2e.sendText(Page.data.intentText, user)` | Default intent is the page name. Language maps are keyed `lang:intent`. |
| `handleArgsText` | ``e2e.sendText(`${Page.data.intentText} ${a1} ${a2}`, user)`` | Args are space-separated; at least one arg is required. |
| `handleCommandText` | ``e2e.sendText(`/${Page.data.intentCommandText}`, user)`` | Default command is the page name. |
| `handleCommandArgsText` | ``e2e.sendText(`/${Page.data.intentCommandText} ${a1}`, user)`` | Space-separated args after the command. |
| `handleCaptionPhoto` | `e2e.sendPhoto({caption: Page.data.name, user})` | Exact caption only; captions match the **bare route name** (e.g. `admin/ban`), not `intentText`. Same pattern for `Video`, `Audio`, `Document`, `Animation`, `Voice`. |
| `handleCommandCaptionPhoto` | ``e2e.sendPhoto({caption: `/${Page.data.intentCommandText}`, user})`` | Exact command caption. Same suffix pattern for the other media kinds. |
| `handleCaptionArgsPhoto` | ``e2e.sendPhoto({caption: `${Page.data.name} ${a1}`, user})`` | At least one arg required. Same for `Video`, `Audio`, `Document`, `Animation`, `Voice`. |
| `handleCommandCaptionArgsPhoto` | ``e2e.sendPhoto({caption: `/${Page.data.intentCommandText} ${a1}`, user})`` | Command caption with args. |
| `handleFreePhoto` / `handleFreeText` / … | Send the same shape with data no other route matches | Dynamic-specific: only runs when defined **on the page's own prototype**, and every matching page handler runs. |
| `handleFree` | Send any unmatched update | Global last resort. Every matching page runs. |
| `handleChatMemberOutIn` | ``e2e.sendChatMemberUpdate({oldStatus: `kicked`, newStatus: `member`, user, chat})`` | Handler suffix is `{old}{new}` in `out` / `in` / `regular` / `admin` buckets, not raw Telegram statuses. |
| `handleMyChatMemberOutAdmin` | ``e2e.sendMyChatMemberUpdate({oldStatus: `left`, newStatus: `administrator`, chat})`` | `out` covers `left`, `kicked`, and `restricted` with `is_member: false`. |
| custom route (`registerCustomRoute`) | Inject the underlying event with `e2e.handleUpdate(...)` | The custom handler is dispatched by the built-in listener for that event. |
| session variants (`handleSession*`) | Enter the state first, then send the matching update | Never dispatched by `handleFree*`; only reachable while `session.method` points at them. |

**Exhaustive family rule.** `handleFree*`, `handleSession*`, and `handleChatMember*` are large generated families. The authoritative runtime lists are `bot.pages.listRouteDynamicSpesific`, `bot.pages.listRouteStaticSession`, and `bot.pages.routeChatMember`; every handler a page defines gets a ledger row and its matching update shape. Do not stop at the common examples above.

### Handler rules

- **Exact and args are different routes.** `handleCommandText` needs `/cmd` with no args; `handleCommandArgsText` needs `/cmd arg`. Test both when both exist.
- **A `handleArgs*` handler is unreachable without args.** A test that sends the bare intent and expects the args handler passes against the wrong route or the fallback.
- **Session handlers need a real entry.** Arm the step through the page's own flow (`sendCallbackQuery` → `setSessionFreeText`) or by continuing a previous step. Calling `handleSessionFreeText` directly is not a test.
- **Non-session handlers auto-clear the pending session** once per dispatch (`_clearSessionOnNonSession`). If the page relies on interruption cancelling a flow, assert that: start a step, send an unrelated routed update, then prove the next free text no longer continues the old flow.
- **`handleFree*` must be defined on the page itself.** Inherited `handleFree*` methods are not dispatched dynamically. A base class that defines one is a routing bug, not coverage.
- **A `handleFree*` test needs input no static route matches.** Static and intent routes win before free handlers; sending a known command and expecting the free handler passes only because the free handler never ran.
- **A handler that produces no API call is `no-match`.** `matched` requires at least one method from `Ctx.ANSWER_API_METHODS` (`send*`, `answer*`, `edit*`, `delete*`, `pin*`, …). A handler that only mutates state and returns can fall through to `hookNotFoundPage`; assert the intended render, or the fallback if that is the design.
- **Every branch inside a handler is an entry point.** `if (input === 'cancel')`, `if (!row)`, `if (step === 'left')` each get a test.

### Intent variants

- `intentTextMap` / `intentCommandTextMap` declare one intent per language. Send each mapped intent with a fixture carrying that `language_code`; a translated intent that no test sends is unverified routing.
- `optionsPage.shortCallbackQueryData: true` replaces the page-name callback payload with a short numeric index. Trigger callbacks through the rendered keyboard (`reply_markup.inline_keyboard[].callback_data`) or `Page.data.callbackQueryData(...).result`, never by hard-coding the page name.
- A page with `static data = this.buildData()` still has intents: `intentText` and `intentCommandText` default to the page name. Test the bare text/command if the handler exists.

## Rule 2 — every render call gets a method-level assertion

Assert the Bot API method, not just "some response". The default `renderText` route is `auto`: a callback edits the originating message, a plain message sends a new one.

| Page call | From a callback | From a message | Assert |
| --- | --- | --- | --- |
| `renderText()` | `editMessageText` | `sendMessage` / `sendRichMessage` (rich) | method + `text` |
| `renderText({mode: 'reply'})` | `sendMessage` / `sendRichMessage` (rich) | `sendMessage` / `sendRichMessage` (rich) | no `editMessageText` |
| `renderText({mode: 'edit'})` | `editMessageText` | `editMessageText` or the documented fallback | no `sendMessage` when the edit succeeds; assert the fallback otherwise |
| `renderPhoto` / `renderVideo` / `renderAudio` / `renderDocument` / `renderAnimation` | `editMessageMedia` | `sendPhoto` / `sendVideo` / … | `media.type`, `media.media`, `media.caption` |
| `renderVoice` / `renderVideoNote` / `renderSticker` / `renderLocation` / `renderContact` | `deleteMessage` + matching `send*` | matching `send*` | delete happened first; payload fields |
| `renderMediaGroup` / `renderPhotoGroup` / … (multi-src) | `deleteMessage` + `sendMediaGroup` | `sendMediaGroup` | `media[]` length, per-item `type` + `caption` (groups cannot edit) |
| `renderEditCaption` | `editMessageCaption` | `deleteMessage` + reply fallback | `caption`, or the reply text on fallback |
| `renderEditKeyboard` | `editMessageReplyMarkup` | throws (no fallback) | `reply_markup` |
| `renderCallbackAnswer` | `answerCallbackQuery` | — | `text` / `show_alert` |
| `renderPreCheckout` | `answerPreCheckoutQuery` | — | `ok` / `error_message` |
| `renderShipping` | `answerShippingQuery` | — | `ok` / `error_message` |
| `renderGuestAnswer` | `answerGuestQuery` | — | result payload |
| `renderWebAppAnswer` | `answerWebAppQuery` | — | `result` |
| `renderInlineAnswer` | `answerInlineQuery` | — | `results` |
| `renderPoll` / `renderDice` / `renderGift` / `renderInvoice` / `renderPaidMedia` / `renderVenue` | the matching `send*` | the matching `send*` | payload fields |
| `renderBroadcastDelete` | `deleteMessage` per recipient | `deleteMessage` per recipient | one call per id |
| `replyWithStream` / `replyWithMarkdownStream` / `replyWithHtmlStream` | drafts + final | drafts + final | `streamCalls()` + final call |

The table covers the common routes. For every other `render*` the page calls, read its JSDoc (it names the Bot API method) and assert that method plus the payload field the template block produces — do not leave a render call unasserted just because it is not listed here.

Rules:

- **Assert the wrong method is absent.** `expect(methods).not.toContain('sendMessage')` is what proves an edit path did not duplicate the message.
- **One primary effect per update.** A single callback must not produce two `sendMessage` calls unless the page intentionally fans out. Duplicate sends are the most common render regression.
- **Every rendered button is a control with a destination.** Press it in a test, or assert its `callback_data` equals the target page's `Page.data.callbackQueryData(...).result` (or the target `intent` when the target has no args). A button whose payload routes nowhere is a dead end that a text-only test cannot see.
- **`renderText` fallback is a separate branch.** If the page passes `fallback`, cover the case where the edit target is unavailable. Do not assume the fallback ran because the test passed.
- **Forced `mode: 'reply'` and `'edit'` are route contracts.** Test them on both a callback and a message when the page can receive both.
- **`render*` return values are not the assertion target.** Assert `e2e.calls` / the returned slice; the return value is a grammY `Message` or `true`.

## Rule 3 — every interactive state gets a test

Model each page as a state machine. For every `g*` object and every `show`/`process` method, cover the states it can produce:

| State | Must be tested when |
| --- | --- |
| First visit | always |
| Happy-path success | always |
| Invalid input | the handler validates (`Number`, regex, enum, length) |
| Empty/missing data | the page reads DB/cache and can find nothing |
| Cancel / back | the page offers the button |
| Repeated press | the action mutates state (double-submit, double-delete) |
| Session expiry | the page sets a TTL or assumes a prior step |
| Denied | a gate or `GuardBase` check exists |

A page with four `g*` states and three validation branches needs at least seven assertions, not one.

## Rule 4 — every guard gets both directions

Use two distinct users: one allowed, one denied.

```typescript
const allowed = await e2e.sendText(`/admin`, adminUser)
expect(allowed.length).toBeGreaterThan(0)
expect(e2e.extractText(allowed[0]!)).toBe(e2e.gmsg(`admin`, `default`, {}))

e2e.clearCalls()
const denied = await e2e.sendText(`/admin`, plainUser)

// Pick the contract the app actually implements — do not assert both.
// A) silent deny (`hookBeforeRoute` returns false with no render):
expect(denied.length).toBe(0)

// B) deny-and-explain for a text update (the hook rendered the denial):
e2e.clearCalls()
const deniedWithMessage = await e2e.sendText(`/admin`, plainUser)
expect(e2e.extractText(deniedWithMessage[0]!)).toBe(`Forbidden`)
expect(e2e.extractText(deniedWithMessage[0]!)).not.toBe(e2e.gmsg(`admin`, `default`, {}))
```

For a callback update, the denial render is usually `answerCallbackQuery` (`renderCallbackAnswer`); assert that method and the absence of the page's normal `editMessageText` render instead.

Rules:

- **`hookBeforeRoute` is silent by default.** A denied page-level gate that renders nothing is a valid, intentional design. Assert `0` calls for it. A denial that *should* explain itself must produce the explanation call; assert that instead. Never assert both contracts in one test.
- **The handler must not run.** Assert the denial output is not the page's normal render (`.not.toBe(e2e.gmsg(...))`), or — for a callback — that the normal `editMessageText` render is absent. Without it, a gate that denies everyone and a gate that was never wired look identical.
- **Page-level denial does not increment `metrics.counts.blocked`; bot-level denial does.** Do not use metrics as proof for a page gate.
- **Bot-level and page-level gates are different tests.** The bot gate runs before routing and drops the whole update; the page gate runs after a route matches.
- **`GuardBase` checks inside a handler** get the same two-direction treatment, even though they are not `hookBeforeRoute`.
- **Observability hooks are behavior too.** If `hookAfterRoute`, `hookUpdate`, or `hookUpdateError` branches on state (`matched`, `no-match`, `blocked`, `error`), drive each state and assert the observable effect (a log sink, a metric counter, a user-visible fallback).
- **Reusing one user id makes the test pass for the wrong reason.** Two ids, two expectations.

## Rule 5 — every declared locale is exercised

A `<g-message lang="id">`, `<g-keyboard lang="id">`, or `intentTextMap` is a product promise. Prove it.

```typescript
const en = await e2e.sendCallbackQuery(intent, enUser)
const id = await e2e.sendCallbackQuery(intent, idUser)

expect(e2e.extractText(en[0]!)).toBe(e2e.gmsg(intent, `default`, {}, `en`))
expect(e2e.extractText(id[0]!)).toBe(e2e.gmsg(intent, `default`, {}, `id`))
expect(e2e.extractButtonLabels(id[0]!)).toEqual(e2e.gkb(intent, `default`, `inline`, {}, `id`))
```

Rules:

- **Use the template helper, not a literal.** `gmsg`/`gkb`/`gmedia` read the same compiled block the page renders.
- **The trailing language argument is the fixture's `language_code`.** `enUser`/`idUser` exist so the assertion cannot accidentally use the default block twice.
- **Cover the fallback.** A user with `language_code: 'fr'` must fall back to the page's default block, not render an empty string.
- **Cover language-routed intents.** When `intentTextMap`/`intentCommandTextMap` maps `id` to a translated intent, send that intent with `idUser` and prove it reaches the same page.
- **One test per page is enough per locale** only if every state shares the same translation coverage. If a specific state has its own translated copy, assert that state too.

## Rule 6 — fallbacks and unsupported shapes

Every project needs a fallback proof for each input family it can receive:

| Input | Test | Expected |
| --- | --- | --- |
| Unknown callback data | `sendCallbackQuery('nonexistent-callback-data')` | `StatusPage` (`gmsg('status', 'nf')`) or `handleFree` |
| Unknown command | `sendText('/definitely-not-a-command')` | fallback page/handler |
| Plain text with no intent | `sendText('hello')` | fallback page/handler |
| Unsupported media | `sendSticker()` / `sendLocation()` | does not throw; fallback path |
| Edit of a message | `sendEditedText('...')` | `handleFreeEdit` if defined, otherwise no crash |
| Channel post | `sendChannelPost('...')` | `handleFreeChannelPost` if defined |
| Chat member transition | `sendChatMemberUpdate(...)` | matching handler, otherwise no crash |
| Keyboard press after state reset | `sendCallbackQuery(intent)` with a fresh user | page renders from scratch |

Fallback tests must also prove **recovery**: after the unknown update, send one valid update and assert it still works. A fallback that poisons the session or throws is not a pass.

Use a fixture that satisfies the app's bot-level gate. The scaffold's `UserGuard` requires `ctx.from.username`; a fixture without one reaches `UserNameNotFoundPage` before the page under test, so the assertion fails for the wrong reason. Test the no-username gate separately as its own case.

## Rule 7 — external boundaries

| Boundary | Rule |
| --- | --- |
| LMDB / SQLite / app DB | Use the real store. Seed in `beforeEach`, purge by user id, assert through the next update — never by reading rows from the test. |
| Worker thread | `await bot.ready` before the first update. Assert observable output only. Give the test a timeout (`it(..., 15_000)`) when the worker does real work. |
| HTTP dependency | Start a real local server with port `0`, inject its URL before bot construction, stop it in `afterAll`. |
| Timers / debounce | Pass the `settleMs` argument of `handleUpdate(update, settleMs)` and assert the post-settle calls; avoid `await Bun.sleep()` unless the delay is the behavior under test. |
| Config / AOT / deploy mode | **Not covered by e2e.** `e2e/setup.ts` bypasses `gramstax.config.ts` and the filesystem walk. Cover config with `tsc --noEmit` + `gramstax build --dry-run`; cover AOT/manifest with a boot test. |

Runtime middleware is app behavior too: if `rateLimit` is enabled, send `max + 1` updates from one user and assert the `hookRateLimited` output (or deliberate silence). `sessionLock` is Redis-only; a memory store auto-disables it, so an e2e with the default store proves nothing about locking.

## The coverage ledger

Keep `e2e/COVERAGE.md` next to the tests. One row per handler and per interactive state. This is the artifact that makes "no gaps" reviewable.

```markdown
| Page | Handler / state | Trigger | Test | Asserts |
| --- | --- | --- | --- | --- |
| start | handleCommandText | `/start` | start.test.ts › renders default | sendMessage + gmsg(start, default) |
| start | handleCallbackQueryData | callback `start` | start.test.ts › callback edits | editMessageText |
| sum-number | handleSessionFreeText (left) | `23` after step left | sum-number.test.ts › step 1 | gmsg(l) |
| sum-number | invalid input | `abc` after step left | sum-number.test.ts › invalid | re-prompt gmsg(l) |
| admin | hookBeforeRoute deny | `/admin` as plain user | admin.test.ts › deny | 0 calls (silent deny) |
| admin | hookBeforeRoute allow | `/admin` as admin | admin.test.ts › allow | gmsg(admin, default) |
| start | lang=id | callback as idUser | start.test.ts › ID variant | gmsg(..., id) + gkb(..., id) |
```

Rules for the ledger:

- A handler row with no test name is a **failure**, not a TODO.
- A test that only asserts `length > 0` does not satisfy a row; record the concrete assertion.
- Delete stale rows when a handler is removed. The ledger is not a history file.
- Commit `e2e/COVERAGE.md` with the suite so the next agent inherits the inventory.

## Machine audit

Three checks, all deterministic:

```bash
bun run scripts/check-e2e-mirror.ts --path .   # layer 1
bun run scripts/check-e2e-handlers.ts --path . # layer 2 + ledger integrity
bun test e2e/                                  # execution
```

`check-e2e-handlers.ts` is shipped in the generated project (and at the repo root
for `--path` runs). It parses `e2e/COVERAGE.md` and fails when:

- a `handle*` defined under `src/pages` has no ledger row for its page;
- a handler row names no test file;
- a referenced test file does not exist;
- an `e2e/*.test.ts` file is not referenced by any row.

The audit is a floor: it proves the handler has a ledger row and that the row
names a real test file. It does not read the test body, so the row's `Asserts`
cell is what records the concrete method, text, keyboard, media, or call-count
proof. A row that says `length > 0` is still a failure of this contract.

It scans `src/pages`; a handler inherited from `src/base` is not in a page file,
so cover it through a concrete page and list it in the ledger. The regex covers
method declarations and class-field handlers (`handleX = async () => {}`).

## Failure recovery

| Symptom | Cause | Fix |
| --- | --- | --- |
| Audit: `has no row in e2e/COVERAGE.md` | A new handler was added without a ledger row | Add the row; name the test file and the concrete assertion |
| Audit: `has no test file` | The row has a handler but an empty `Test` cell | Point it at the mirrored test and a real case |
| Audit: `test file ... does not exist` | Renamed or deleted test, stale row | Update the path or delete the row |
| Audit: `is not referenced by e2e/COVERAGE.md` | New test file, no ledger row | Add a row, or delete the orphan test |
| Test: zero calls | Guard denied, intent mismatch, or session not armed | Inspect `e2e.calls`, the fixture, and the preceding update |
| Test: `Received "sendRichMessage"` | The page renders a rich template | Assert `sendRichMessage` or use `extractText` |
| Test: extra calls | Missing `clearCalls()` between steps, or duplicate render | Clear between updates; assert the method set |
| Test: `answerCallbackQuery` absent | The page never calls `renderCallbackAnswer` | Do not expect it; add the block if the UX needs it |
| Ledger passes but behavior is untested | `Asserts` says `length > 0` | Record the method, text, keyboard, media, or call count |

## No exception rows

The gate does not accept an "uncovered" row. A handler that cannot be observed
through an update is either dead code (delete it) or missing a reachable trigger
(add the page/route that exercises it). "Hard to test", "needs a real token", and
"the mock does not support it" are not exceptions: use `e2e.handleUpdate()` to
construct the missing update shape, or move the behavior behind a page the helper
can reach.

## Definition of done

- [ ] `check-e2e-mirror` exits 0 (no missing, no orphan tests).
- [ ] `check-e2e-handlers` exits 0, and every ledger row names a concrete assertion.
- [ ] Every `handle*` in the page tree appears in the ledger and in a test.
- [ ] Every mapped intent (`intentTextMap` / `intentCommandTextMap`) and every rendered button is exercised.
- [ ] Every `render*` call has a method-level assertion on the intended route.
- [ ] Every interactive state has a success + failure test.
- [ ] Every gate has allow + deny with two user ids.
- [ ] Every declared locale is asserted with `gmsg`/`gkb`/`gmedia`.
- [ ] Unknown callback, unknown command, and one unsupported shape land on a fallback and recover.
- [ ] External boundaries are real, cleaned up, and bounded by a timeout.
- [ ] `bun test e2e/` passes from a clean checkout.
